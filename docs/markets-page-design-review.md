# Markets 风控页面 — 设计评判简报(请 Codex 批判整体展示逻辑)

## 1. 用户与目标
- 终端用户:私人银行 RM / IC(金融专业人士)。
- 痛点:所在机构信息过载,很难及时根据市场信号得到"市场风险"的提示。
- 这个页面的唯一核心价值:**直观告诉用户当下美股是"噪音"还是"真崩盘"**,并展示支撑该判断的客观机制证据。
- 合规边界:只做客观 regime 判读,**不生成面向客户的话术、不给买卖建议**(措辞用观察式,不用 directive)。

## 2. 心智模型(verdict-first + 4 机制刹车)
顶层一个判定,4 状态(轴是"有没有机制在 confirm",不是"价格在不在跌",以免把"信用先于价格断裂"埋成平稳):
- 🟢 STABLE 平稳 / 🟡 BREAK_FORMING 形成中 / 🔵 NOISE 噪音回调 / 🔴 CONFIRMED_BREAK 确认断裂
- 三个"能确认崩盘"的机制刹车:**信用**(利差走阔加速/CCC 领先/股信背离)、**利率**(实际利率 8 周重定价压垮久期,2022 型)、**基本面**(AI capex/营收背离,2000 型)。
- **拥挤**只抬警戒、不单独 confirm。
- 保守默认:疑似偏 STABLE/NOISE;信用需 ≥2 信号 corroborate + VIX 交叉,避免误报(经验:~75% 回调是噪音,信用利差是区分噪音与熊市的领先尺)。

## 3. 当前页面结构(三层)
```
[判定 HERO — 扁平无卡片]
美股风险预警                       更新至 06-16  ⓘ
  ●  平稳                                        ← 圆点+状态词带色
  市场整体平稳;利率出现初步异动、拥挤度偏高,但均未确认,暂未对股市构成系统性风险。   ← 白色解读
  留意 · 信用利差 平稳 · VIX 17.7 · 实际利率8周 +27bp · 纳指距高点 -0.3%        ← "留意"暗、数值较亮
──────────────────────────────────────────
[4 机制一览 — 密集行,细横线分区]
风险机制
信用    正常    HY利差 275bp · CCC领先 36bp · 股信背离 无   ›
利率    异动    10Y 4.49% · 4周变化 13bp · 10Y-2Y 41bp   ›
基本面  正常    SOX偏离 +71% · capex评审 Q1 2026   ›
拥挤    偏高    集中度 38.6% · 宽度 57% · VIX 17.1   ›
[点任意机制 ▸ 展开 = 旧的丰富指标详情(band/velocity/notes)]
```
机制行:机制名(左)· 状态色字(正常/异动/恶化/偏高)· 证据(右,标签暗+数值亮 mono)· chevron 展开。

## 4. 视觉处理(目标:彭博终端,不是消费卡片)
- 扁平、细横线分区,无圆角 surface 卡片。
- 颜色只做 accent:状态圆点 + 状态词 + 机制状态字(绿/黄/红)。
- 四级亮度层级:状态色 > 白色解读 > 亮数值 > 暗标签。
- 等宽字体放数字。

## 5. 演进历史(为什么长这样)
- 一开始是"带背景色的卡片 + 旧的 低/中/高/极高 severity 条",用户反馈:冗余(两个 verdict 叠一起)、不够彭博、文案黑话(置信低、利率形成、credit regime/BREAK)。
- 已改:删 confidence、删 低中高极高、删 hero 内重复的 4 个 brake chip、黑话→市场语言、卡片→扁平、9 个旧指标按 4 机制重组。

## 6. 我(开发者)自己仍觉得别扭、想请你重点批判的点
1. **判定 HERO 的"留意"行** 和下面 4 机制一览的数据**有重复感**(留意行的 VIX/实际利率/纳指,机制行也有)。到底该不该保留留意行?还是该精简成"只点出正在异动的那一项"?或干脆并入 one_line?
2. **信息流是否最优**:HERO(判定+解读+留意)→ 4 机制一览 → 展开详情。三层之间的信息分工是否清晰?有没有更好的 IA?
3. **4 机制分组的合理性**:VIX 归到"拥挤"是否牵强(它是波动率,不纯是拥挤)?F&G 情绪目前被丢弃了,要不要回来?实际利率 8 周(DFII10,利率机制的关键证据)目前只在留意行、没进利率机制行(因为它不在 snapshot.indicators 里)——这是个数据缺口。
4. **"留意行"措辞**:`信用利差 平稳 · VIX 17.7 · ...` 把"状态词"和"纯数字"混在一行,不统一。
5. **整体是否还是"dashboard 思维"**:用户要的是"一眼 noise vs break"。现在 HERO 给了判定,但下面 4 机制 + 展开会不会又把人拉回"看一堆指标"?如何在"给结论"和"给证据"之间取得更好的平衡?
6. **状态词 vs 机制状态词的语义区分**:顶层"平稳/噪音/形成/断裂" vs 机制"正常/异动/恶化/偏高"——两套词会不会让用户混?
